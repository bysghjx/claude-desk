# Claude Desk

面向 Windows 的本地 Claude Code 工作空间。无需注册 Claude Desk 账号；直接使用本机官方 Claude CLI 及 `~/.claude/settings.json` 中的服务商配置。

## 启动

打包版：双击 `ClaudeDesk.exe`。选择项目文件夹，输入任务即可。

源码版：安装 Node.js 后运行 `npm ci`，再运行 `npm start`。

需要官方原生 Claude CLI：`%USERPROFILE%\.local\bin\claude.exe`。客户端优先使用这个路径。客户端不安装、修改或替换你的 Claude 配置。

## 交互

- 启动默认进入主页，不自动打开项目或旧会话；在主页手动选择项目，在左侧点击已有会话继续。点击“新任务”回到主页。选择项目之前不会自动创建空白会话。
- 首页输入框固定在底部，项目选择和轻量快捷建议保留在中间；会话内显示回复与项目文件面板。
- 左侧添加项目、搜索和切换会话，Ctrl+N 回到新任务主页。点击项目只选择项目，不创建空会话；首次发送非空消息后才创建会话，重复发送有防抖保护。
- 每轮回复底部可“删除这轮”；左侧会话行悬停或键盘聚焦后显示删除按钮，可删除整个会话。两种删除均使用应用内深色确认弹窗，默认聚焦取消，Esc 或点击外部取消。运行时先停止才能删除某轮；删除整个会话会停止该会话的任务。删除记录不会回滚项目文件。
- 删除某轮后会关闭旧 CLI，上下文从剩余问答重建；删除会话也会移除该会话草稿，恢复备份同步更新，避免普通恢复把已删记录带回。
- 点击模型按钮先打开紧凑思考面板：当前强度、模型名称与蓝色五档滑块；点击模型名称展开模型列表，选择后返回思考面板。模型列表支持搜索、刷新和自定义模型 ID。点击外部或输入框关闭；Esc 从列表返回思考面板，再按 Esc 关闭。切换应用时关闭。
- 输入 `/` 选择本地命令，`@` 引用项目文件，`@@` 引用其他已有会话；在输入框首行 / 末行按上下键召回当前会话的已发送消息。引用会作为上下文明确发送给 Claude。
- 中间显示 Markdown 回复、工具调用及输出。工具请求需要批准时，在输入框上方显示批准卡片。
- 底部运行条展示真实阶段、累计耗时和最后事件时间；25 秒无事件时明确说明正在等待，不虚构生成进度。
- 发送键左侧的圆环显示上下文占用百分比；点击查看上下文 tokens、CLI 返回的上限、剩余空间和统计模型。使用最近主会话响应的输入、缓存读取、缓存写入及输出 tokens，不累加整段会话的请求总量。数据缺失显示“—”；草稿、下一次请求和服务商账户余额不在统计内。
- 输入框 Enter 发送、Shift+Enter 换行；运行中发送键变为停止键。停止会终止该会话的 Claude 进程。
- 右侧查看 Git 改动与文本 diff，或浏览本地文件。它不会自动提交、暂存或回滚你的代码。
- 权限菜单包括“手动批准”“允许编辑”“仅做计划”“自动审批”“未授权即拒绝”“完全访问”六种模式。默认手动批准；自动审批需要 CLI、模型和服务商支持，不可用时保留 CLI 返回的具体原因。“完全访问”是显式选择的高级模式，跳过常规权限提示；其他模式不会设置 SDK 的跳过权限标志。已有权限规则及组织策略仍可能限制操作。设置从下轮消息开始生效。
- 设置面板显示 CLI、服务商和配置位置；可从已有服务商读取模型列表。密钥保留在主进程和现有 CLI 配置中，不进入渲染界面。

## 会话与上下文

每个活跃会话使用独立、持续运行的 Claude CLI 子进程，连续消息复用该进程上下文。不会使用临时 HOME，也不依赖第三方客户端创建的 resume ID。

项目、聊天、草稿、引用和模型选项统一保存在 `%APPDATA%\ClaudeDesk\data\workspace.json`。正式版始终使用这个目录，不受预览环境变量影响。写入先同步到临时文件，再原子替换，并保留上一份有效 `.bak` 备份；启动时可恢复完整的临时存档或有效备份，文件损坏时不会静默覆盖历史。

主页默认不选中历史记录，这不表示旧记录被删除；左侧“全部项目”可显示所有历史。未发送草稿随所属会话保存，主页草稿独立保存。首次升级会合并已知旧版预览目录里的记录并按会话 / 消息 ID 去重。

应用关闭会停止活跃任务。重新打开后，手动选择历史会话继续，或停止后继续、切换模型/权限/思考深度时，会从本地保存的对话重建上下文；界面标记“从本地历史恢复上下文”。恢复上下文最多保留约 120,000 字符，之前的完整记录仍可浏览和导出。

第一版不包含云同步、后台开机启动、浏览器控制、语音、图片附件或编辑器自动补全。Git 面板展示整个项目当前改动，不声称这些改动全部由本次任务产生。

## 开发与验证

`npm test`：状态转换、错误结果、批准、停止、实时流去重、多轮进程复用与重启上下文恢复。

`node scripts/live-test.cjs`：使用现有服务商进行最小真实多轮和重启测试（会产生少量模型用量）。

`npm run package`：打包 Windows x64 可运行文件夹。

## 常驻信息框与子智能体

右上角常驻显示“输出内容、来源、子智能体”。正文和输入框为信息框预留宽度，信息框不覆盖文字；文件、来源和子任务内容在框内滚动。来源汇总本会话引用的 @ 文件及 @@ 会话。

Claude 的 Agent / Task 调用会创建独立的子任务记录，按 parent_tool_use_id 分流输出与工具调用，任务生命周期、后台状态、进度和用量由 CLI 事件更新。子智能体详情可展开，嵌套任务有标记。主回复完成后若仍有子任务运行，客户端继续显示运行状态。

多个并行权限申请会排队展示，标明子智能体来源，批准一个不会自动批准其他请求。停止会话会终止其 CLI 并标记子任务已停止；重启后原来仍在运行的子任务显示已中断，保留其已有输出。CLI 没有提供的子任务输出、进度或用量不会补造。

子智能体卡片在折叠时也显示最新进展、最近工具 / 目标和耗时。主页汇总全部会话里仍在运行的子智能体；进入会话后显示该会话的完整子任务记录。主页卡片详情中可进入所属会话。没有真实任务时显示明确的空状态，不展示预览数据。

## 插件、技能和累计用量

左下角新增“插件、技能、用量”入口，在统一的管理窗口切换。

- 插件：读取本机 Claude CLI 的已安装插件和市场目录，支持搜索、按名称安装、添加 HTTPS / GitHub 市场、启停、更新及卸载。卸载保留插件持久数据；客户端不自动确认市场声明的安装命令，也不代填登录或密钥。需要这些流程的插件会显示 CLI 返回的原因。
- 技能：发现用户、当前项目和已启用插件的技能。可新建、导入包含支持文件的技能文件夹；本应用副本可编辑和移除，外部技能只读。技能库通过本地插件 `desk-user-skills` 加载，选择“全部”或“只加载所选”。修改后下一次发送会重建 CLI 并恢复聊天上下文，当前运行不重启。技能选择不是文件沙箱。
- 累计用量：按今天、7 天、30 天或全部时间，结合项目筛选；展示输入 / 输出 / 缓存读写 tokens、估算费用、按模型汇总和日期趋势，可导出 CSV。新版采用 SDK modelUsage 的增量统计，包含其报告的子任务消耗。旧记录和只返回主任务计数的 CLI 标记为明细不完整。统计仅覆盖本应用实际保存的事件，不代表服务商账单或账户额度。
- 删除会话或某轮问答后保留不含聊天正文的用量计数；模型名称、时间、项目 ID 和计数用于筛选，不保存提示词、回复或密钥。

### v0.9.0：统一会话数据
正式数据位于 `%USERPROFILE%\.claude-desk\data`，避免 AppData 在打包应用子进程中重定向到另一副本。`workspace.sqlite` 是权威存储，WAL + FULL 同步事务保存；每个会话独立一行，仅更新变化记录；`sessions` 保留当前会话 JSON 副本。删除会话或轮次写入无正文的审计记录，独立副本同步清理。启动不会从副本自动复活已删除记录。
首次迁移合并旧正式目录和 Codex 包缓存目录，保留较新内容、草稿和用量；`migration-backup.json` 是迁移前的完整快照，之后不会随删除更新。旧 JSON 保留用于回退，旧版软件不认识新数据库，请只用新版。设置页展示数据库、数据集 ID、版本和会话数量，并可备份全部数据。SQLite 损坏时保留原件并报错，不自动清空或回退到旧记录。


### v0.9.1：独立子智能体窗口
点击右侧子智能体卡片，在独立窗口查看任务、状态、文本输出、CLI 返回的思考内容和工具记录。多任务可分别开窗，同任务重复打开聚焦现有窗口。支持复制输出、跟随输出与返回主会话；关闭查看窗口不停止任务。审批仍在主会话完成。历史子任务从 SQLite 原记录打开，不创建新会话。窗口只展示 CLI 实际返回的信息，不能直接给已委派的任务发送新消息。

### v0.11.0：更接近 Codex 的体验
- 对话流：每轮按真实顺序记录说明文字、思考和工具调用。最终回复之前的过程折叠为「已处理 3m 12s · N 个步骤」，运行中自动展开。工具按 Codex 风格显示为「运行 `命令`」「读取 文件」「编辑 文件 +12 −3」（可展开行级 diff）「搜索」「更新计划」（清单）等。回复下方汇总本轮改动的文件，点击「审查改动」在右侧打开对应 diff。旧记录和 Codex 导入的会话同样适用。
- 侧栏：会话挂在所属项目下，项目可折叠，项目旁「＋」直接在该项目新建任务。会话的「⋯」菜单支持重命名（也可双击顶部标题）、置顶、归档和删除；底部「已归档」查看和恢复归档会话。
- 运行中继续发消息：任务运行时按 Enter 会把消息加入该会话的队列，本轮正常完成后自动发送。出错或停止时队列保留，可「立即发送」（先停止当前运行）、「编辑」或删除。输入框为空时发送键才是停止键。
- 图片附件：在输入框粘贴截图、拖入图片或点图片按钮添加（PNG/JPEG/GIF/WebP，每张 ≤ 5 MB，每条最多 6 张）。原图保存在数据目录的 attachments 中，以图片块发送给 Claude；消息里显示缩略图，点击用系统程序打开。删除会话或该轮问答时一并删除图片。重建上下文时历史只记录图片数量，不重发图片。
- 改动审查与提交：右侧「改动」按文件显示新增 / 修改 / 删除和 +/− 行数，可逐个或全部暂存，可撤销单个文件（新文件会被删除，需确认），填写说明后提交（未暂存任何文件时提交全部改动；Ctrl+Enter 提交）。不会推送到远程。项目是仓库子目录或仓库尚无提交时也可使用。

### v0.12.0：界面架构重构
界面从 7 个共享全局变量的脚本改为 ES 模块，主窗口通过受限的 `app://desk/` 协议加载（只开放 `ui/` 和 marked、DOMPurify 两个库）。依赖只朝一个方向：

- `ui/src/core`：DOM 工具、状态格式化、状态仓库（事件订阅）、提示条与确认框。
- `ui/src/lib`：纯函数（过程拆分、工具行、行级 diff、速度统计），不访问 DOM，可在 Node 中测试。
- `ui/src/features/actions.mjs`：选择会话、发送 / 排队、删除、重命名等全部业务动作，只通过参数拿到 api、仓库和输入框接口，不访问 DOM。
- `ui/src/views`：侧栏、对话、单轮、状态栏、输入框、右侧面板、改动审查、管理窗口、分栏和窗口外框，各自订阅仓库事件，不互相读写。
- `ui/src/main.mjs`：创建并连接以上模块。

渲染改为增量更新：每轮对话是持久的 DOM 节点，只有版本号变化的轮次、内容变化的步骤才会重写；`<details>` 元素保留，展开状态和过渡动画不会被打断。主进程为每轮生成版本号快照，已结束的轮次复用缓存，只把变化的轮次发给界面（未变化的只发 `{id, rev, same}`）。样式由 `scripts/merge-css.cjs` 合并为 `ui/app.css`：按原层叠顺序删除被同一选择器后续完全覆盖的 298 条声明，合并前后计算样式逐项一致。

### v0.13.0：动画
只有新出现的内容会动：运行中新追加的步骤和新的一轮上浮淡入，最终回复开始出现时淡入，一轮结束时过程组平滑收起、改动汇总和底栏依次浮现；切换会话时整页淡入，历史内容不逐条重播。过程组、步骤、思考和子智能体卡片的展开收起是高度过渡（CSS `::details-content`）。菜单、模型 / 权限选择、对话框、提示条、批准卡片、排队列表、子智能体分栏有出现动画；按钮有悬停和按压反馈，图标栏名称提示延迟淡入。系统开启「减少动画」时全部关闭。动画样式集中在 `ui/app.css` 末尾的 Motion 分区，时长和缓动曲线是 `--motion-*` 与 `--ease-*` 变量。

窗口不在前台时，任务完成、运行出错、Claude 或子智能体请求批准、用 AskUserQuestion 提问、计划等待确认，都会发一条 Windows 通知；点通知会打开对应会话，任务栏图标同时闪烁。同一个请求只提醒一次；有排队消息时只在最后一条完成后提醒；手动停止不提醒。判断逻辑在 `notify.cjs`（纯函数，见 `test/notify.test.cjs`），显示由 main.cjs 负责。设置 → 通知可以关闭，也可以发送测试通知。Windows 只给带 AppUserModelID 的程序显示通知，所以打包版首次启动会在开始菜单创建「Claude Desk」快捷方式（指向当前 exe）。外观选项改为分段按钮：跟随系统 / 月之亮面 / 月之暗面，使用线条图标。

### v0.16.0：更像 Codex 的四项能力与界面整理
- **提问与计划卡片**（`ui/src/views/approval.mjs`）：AskUserQuestion 的选项变成可点的按钮。只有一个单选问题时点一下就提交，多选或多个问题时选好再提交，也可以选「其他」自己输入。计划确认（ExitPlanMode）按 Markdown 显示，有三个选择：「执行并自动接受编辑」「执行，改文件前问我」「继续修改」（可附修改意见）。批准计划后会话会切到相应的权限模式。
- **回退到这里**（`checkpoint.cjs`、`ui/src/views/rewind.mjs`）：每轮开始前，项目文件会记录到数据目录下的私有 git 对象库（按文件夹区分），完全不碰项目自己的 .git、索引和分支，照常遵守 .gitignore，跳过超过 10 MB 的文件和依赖目录。悬停在你的消息上点「回退到这里」：先预览会改回、恢复、删除哪些文件，再删除这一轮及之后的问答，可以同时恢复文件，提问放回输入框。应用重启后也能回退。
- **独立工作树**（`worktree.cjs`）：主页可以选「本地项目目录」或「独立工作树」。选工作树时，会从当前提交新建 `claude-desk/xxxxxx` 分支和文件夹（数据目录 `worktrees/`），Claude 的改动不影响主目录。右侧「改动」顶部可以看到状态、合并到主目录当前分支（no-ff；有冲突自动取消），或者移除工作树（分支合并过才删除）。移除前会结束这个会话的 CLI 进程和终端，避免 Windows 锁住文件夹。
- **终端**（`terminal.cjs`、`ui/terminal.html`、`ui/src/views/terminal.mjs`）：顶部「终端」或 Ctrl+` 在右侧打开 PowerShell（有 pwsh 时优先用 pwsh），基于 node-pty / ConPTY，每个项目或工作树一个 shell，切换会话时保留。xterm 会写 `<style>`，所以终端放在单独的同源 iframe 里，该页面允许内联样式。主窗口仍然是 `style-src 'self'`。打包时 node-pty 解包在 asar 外。
- **侧栏状态点**：只在运行中、等待你批准，或有你还没看的新回复（绿点，出错是红点）时显示。打开会话即视为已读（`seenAt`）。
- **强调色**：设置 → 外观 → 强调色，有默认（中性灰白）、橙、蓝、绿、紫、粉、黄。会影响发送按钮、主要按钮、开关、链接、焦点框、选区、当前会话指示条和未读点。浅色主题使用加深的版本。
- 其他：项目图标换成文件夹；审批卡片样式限定在 `#approval`，修复等待批准时侧栏状态点被撑大；输入框提交改为同步阻止，避免表单真的提交；`app://` 响应加 `cache-control: no-cache`，避免更新后读到旧文件。

### v0.17.0：窗口材质与细节
